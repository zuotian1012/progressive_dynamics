# 旧自写渐进求解器失败诊断

对象是 output/bunny_paper_scale/velpro 的 L0 第57步，不是正在运行的原生 C-IPC。

## 已确认的直接原因

最后接受步为56。第57步迭代1000次仍未达到1e-4的RMS速度增量阈值，程序按本地迭代上限报错。最后900次迭代均被线搜索接受，但总能量下降仅1.7192e-13；最后一次下降1.8562e-16。最后步长1.4901e-8，略高于本地预览早停门槛1e-8，未触发早停。速度增量仍为.00336341。线性求解相对残差约1e-12，不能将失败归为线性方程未解准。

## 固定失败步的数值验证

scripts/diagnose_bunny_stall.py 从最后接受状态重建同一个增量问题，在独立输出中单线程回放80次；未改原实验、物理参数、容差或正在运行的C-IPC。回放再次出现停滞，末次增量.00336683，alpha=4.7684e-7，线性相对残差1.8371e-12。诊断迭代点不是接受轨迹，不能渲染成仿真成果。

在这个停滞点，将新的Newton方向归一化后：

- 实现采用的近似梯度预测方向导数为 -2.51794568e-4。
- 冻结偏移能量的中心差分方向导数约 -2.51795e-4，与梯度吻合。
- 线搜索实际使用的完整非线性偏移能量，中心差分方向导数在epsilon=1e-5、1e-6、1e-7、1e-8时分别为 +1.8917e-8、+1.4723e-8、+1.2256e-8、+1.7347e-8。

因此，该诊断点的搜索方向对冻结偏移模型下降，却对实际线搜索目标几乎平坦、数值检查为微弱上升。它解释了反复缩小步长、能量几乎不动而近似Newton增量不收敛的机制。正方向导数很小，必须保留数值精度限制；这不是整个真实梯度或所有可能方向的检测，也不能将本次诊断点称作原始第1000次迭代点。

代码位置：progressive/solver.py 的 evaluate 使用 U.T @ gfine，solve 的 nonlinear 线搜索重新计算offset；ShellProlongation.offset依赖当前几何。

论文 PD2024 §4.6明确采用冻结非线性偏移的近似梯度，并允许粗层非下降时退出。因此不能把“没有对偏移求导”本身宣布为抄错公式。现有重建输入上的近似方向和真实目标失配，加上对停滞敏感的本地终止策略，是已观测到的失败机制；还未证明这是唯一根因或已经找回作者完整停止实现。只增大上限、放宽容差或强行接受不能证明复现成功。

## 粗层重复性

VelPro与Full的源码和资产SHA相同，参数仅方法名与输出目录不同，L0预测公式相同。前10步轨迹一致，第18步预览早停迭代数20与18不同，第56步最大坐标差约.15993m。Full第57步也未Newton收敛，而是line_search_failed预览早停。说明Full继续运行不能证明其解决了同一问题；具体浮点差异的起源尚未定位，不能未经验证归咎于线程。

证据：output/bunny_failure_diagnosis/diagnosis.json、replay.json；原始失败记录 output/bunny_paper_scale/velpro/velpro_L0/solver.json。
