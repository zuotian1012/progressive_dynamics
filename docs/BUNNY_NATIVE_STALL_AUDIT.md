# Bunny 原生 PSQ 失败点对照（2026-11-16）

后续已接入粗层非下降预览停止，并完成25步短测及严格模式对照，见 [BUNNY_COARSE_PREVIEW.md](BUNNY_COARSE_PREVIEW.md)。下文保留策略修改前的诊断结论。

本次只分析 Bunny cloth，不运行叠衣。结果目录为 `output/bunny_stall_audit_20261116`，结构化结果为 `audit.json`、`controls.json`。原始日志和已接受轨迹均保留。没有修改物理参数、收敛容差或接受策略，没有强制接受，也没有将诊断试探点作为动态帧。

## 结论

已定位此次 L0 第18步的直接停滞机制：组装的冻结偏移梯度给出的方向，对冻结偏移目标下降，但对线搜索所评估的完整非线性 PSQ 目标上升。应变、接触扫掠、CCD和CFL在这个诊断点没有缩小可用步长。由此应优先处理近似梯度、完整目标线搜索与粗层停止策略之间的配合，而不是增加Newton预算或放宽阈值。

这不是所有求解代码正确性的证明，也没有证明完整真实梯度为零。不能把此处方向不下降解释为完整能量已经收敛，更不能直接推广到衣服失败。

## 同位置、同方向的配对实验

重新运行当前原生模型到第18步失败。诊断在回溯失败之后执行：先计算正常完整能量；恢复到失败迭代位置，再保存 `x0` 和 `P(x0)`，用 `P(x0)+U(x-x0)` 评估冻结偏移的弹性能量。惯性、接触、摩擦及应变项保持相同，方向也保持相同。结束后关闭冻结开关并恢复迭代位置。

此构造在基点严格复用 `P(x0)`，两种目标的基点总能量一致：8.686952712029685e-8。仅沿已检查的正向碰撞扫掠范围试探，不沿未经CCD检查的反方向试探。

| 1e-2 | -7.73158467e-13 | +5.59281561e-15 | -7.72493042e-13 |
| 1e-3 | -7.73158467e-13 | +4.92580099e-15 | -7.73091868e-13 |

在alpha=1e-4处冻结目标的差分斜率相对预测误差约9.28e-6；四个尺度完整目标斜率均为正。因此不是只在末次回溯的舍入极限处出现能量增加。小尺度结果仍受浮点精度影响，不应过度解释其末位。

此时strain_alpha、swept_alpha、ccd_alpha、cfl_alpha均为1。随后正常回溯缩小到约4.66e-10仍失败。说明该点是线搜索目标不下降造成停滞，不是可行步长限制先卡住，也不能仅靠改善近似Hessian的速度来解释全部现象。

## 重复性与控制组

- 修改诊断前的baseline和修改后的paired均只接受17步，均在第18步失败。共同已接受前缀最大位置差7.56e-10 m；不是逐位一致。失败的零基Newton索引分别为23与22，不能假称两次在同一次迭代停止。关键配对斜率全部来自paired内部同一迭代点。
- 两次运行的资产、bundle、场景配置、材料与初始拉伸一致，构建前后DLL摘要分别保存在run.json。新增诊断不用于性能比较。
- 恒等映射U=I、零偏移、初始拉伸1.045的两步原生/PSQ对照均收敛，最大位置差2.1272e-11 m，小于预设1e-9 m。
- 使用原生粗层弹性、保留同一硬应变屏障和接触配置的reference控制完成18/18步，零强制接受。该组改变弹性离散模型，轨迹与PSQ不同，不是同增量问题的性能或物理等价对照。
- 本轮全部五次运行均无强制接受。失败诊断状态未写入accepted_positions.npy。

## 与论文的关系及后续修复方向

本地 `tmp/pdfs/paper2.txt` 的PD2024 §4.6明确使用冻结偏移梯度，并允许最细层以下预览在方向不再下降时退出；最细层仅在Newton收敛时退出。当前原生分支将L0也按严格Newton处理，没有实现对应预览停止策略。因此“冻结偏移不求导”本身不是新发现的公式抄错；近似求解与终止语义的接入不完整，才是当前最应处理的问题。

若目标为论文复现，下一步应实现和验证明确区分层级的停止状态：L0非下降退出标为preview_non_descent，保留当前可行迭代点，不能应用一个不下降的强制更新，不能标为Newton收敛；最细层仍严格收敛。非下降检测本身需要有数值尺度依据，不能简单把任何回溯失败都改名为预览成功。随后短测预览质量和真正细层收敛。

若另有“粗层也必须严格求解完整PSQ能量”的目标，应独立构造完整Jacobian梯度或真实下降方向的诊断分支；这是对论文近似求解的变更，需要单独标记。本次没有实施这两类算法修改，也没有把冻结偏移能量替换为正式线搜索目标。

## 代码及复现

新增诊断接口位于 `native/libuipc/psq_proxy.h/.cu`，仅在失败诊断中启用；配对探针位于 `psq_direction_audit.inl`。`scripts/report_bunny_stall_audit.py`检查配对记录、输入一致性并输出结果。独立源码构建成功，恒等控制通过，报告脚本语法检查通过。

```powershell
.venv/Scripts/python.exe native/libuipc/prepare_native_build.py --with-psq --build
.venv/Scripts/python.exe scripts/run_psq_probe.py --bundle output/libuipc_psq_native/L0_to_90k.bin --steps 18 --direction-audit --output output/NEW_BUNNY_AUDIT
```

该命令预期仍在第18步失败；它用于定位原失败，并非修复验收。原生日志中 `PSQ_DIRECTION_AUDIT`、`PSQ_FROZEN_AUDIT` 和 `PSQ_AUDIT_CAPS` 分别保存完整目标、冻结目标与步长限制证据。
